# Wxview v0.6.0

本版合并 Windows 实验性取钥、已提交 WAL 快照、查询读取状态，以及移除消息索引的修复（PR #8、#9、#10、#11）。

## 变化

- Windows 新增 Config.Cipher 内存取钥路径，并继续用数据库首个页面的 HMAC 验证密钥。仍属实验性能力，尚未完成 Windows 微信实机验收，不代表微信 4.2 已兼容。
- 刷新可读取已提交但尚未 checkpoint 的 WAL 事务；不修改微信原库、WAL 或 SHM。采集遇到持续写入且无法取得稳定快照时会明确报错，保留旧缓存。
- 消息 JSON 与 WebAPI 响应增加 `meta.data_coverage`，报告实际读取缓存的覆盖范围、新鲜度与缺口。它描述本机已同步数据，不能证明手机聊天已完整同步。
- 移除 Wxview 派生消息索引，消息、时间线和搜索直接读取解密分片，修复旧索引导致已缓存消息漏查的问题。默认也跳过微信 `message/message_fts.db` 的取钥、监听与解密；搜索不依赖微信私有分词器。

## 升级

1. 下载对应平台包，核对 `SHA256SUMS`，替换二进制。`wxview version` 应只输出 `0.6.0`。
2. 已有有效密钥与解密正文缓存可继续使用，无需删除 `~/.wxview` 或重新取钥。旧刷新元数据缺少版本绑定时，读取状态先显示 `unknown`；下一次正常刷新会补齐绑定。
3. 若运行着旧版 daemon 或 API，替换二进制后自行停止并重新启动。旧进程不会自动更新，新版启动仍需终端交互确认。
4. 使用 `wxview index` 的脚本需删除该步骤。旧 `--no-index` 仍兼容，但不再出现在续页参数中；WebAPI 忽略旧 `no_index` 参数。

消息项结构和分页游标契约保留。查询返回 `query_mode=scan`、`index_used=false`；旧索引状态、原因及延迟字段已移除。程序不会自动删除旧 FTS 解密副本或旧派生索引，也不会清理微信原库。

多会话时间线改为直接扫描，开销可能增加：历史本机样本中，20 个活跃会话查询一天、取 50 条，耗时从约 0.17 秒增至 6.0 秒；该样本两条路径返回相同结果。自动化调用宜指定会话、较窄时间范围和条数。

## 验证范围

- macOS Apple Silicon / 微信 4.1.13 已验证取钥及两轮 WAL-only 新消息读取。Intel / 微信 4.1.15 有取钥和基本查询验证记录。
- Windows 原生 CI 验证合成测试、构建和发布包的版本及帮助入口；这些检查不等同于 Windows 微信实机验收。
- 发布包覆盖 macOS ARM64、macOS AMD64、Windows AMD64，附 SHA-256 校验文件及第三方许可。二进制内嵌构建版本，包内 `BUILD-INFO.json` 记录来源提交；不会打包账号数据、密钥或聊天内容。
